Who plays, and for how long

This stage takes last season's starts, this season's matches, RotoWire lineups and the FPL status flag. It hands on three odds per player (start, cameo, no appearance) and the minutes they imply.

§4.1Historical signal

In short: last season's share of starts and share of sub appearances give the model a starting guess for each player.

sample = max(matches, starts, ceil(minutes / 90)) startRate = starts / sample cameoRate = clamp(max(0, appearances - starts) / sample, 0, 1 - startRate)

starts comes from the recorded starts count when present. Otherwise it counts matches with minutes >= 60. Start and cameo minute averages come from the top-starts rows and the remaining appearance rows.

This is the seed only. This season's completed matches update the start estimate through the EWMA (§4.1.1), and keep doing so after 240 observed minutes.

§4.1.1Current-season update

In short: after each match the start estimate moves 40% of the way toward what just happened (1 for a start, 0 for no start).

p0 = previousSeasonStartRate // §4.1, or the §4.2 fallback pn = (1 - alpha) * p(n-1) + alpha * startedThisMatch alpha = START_RATE_ALPHA = 0.40

The spec's example: a 20% starter who starts five matches in a row.

Check: 0.6 × 0.20 + 0.40 = 0.520. Then 0.6 × 0.520 + 0.40 = 0.712, then 0.8272, 0.89632 and 0.937792.

Cameo is derived, not run alone: cameo = clamp(pAppeared - pStart, 0, 1). pAppeared is the same recursion over minutes > 0, seeded at startRate + cameoRate.

lib/availability/startRate.ts · blendStartRate

Why no sample-size shrinkage

Unlike blendPlayerRate (§6.3.1) and blendInSeasonForm (§5.2), this recursion has no sample-size shrinkage. That is deliberate. A role is a fact about the present, not an average over the season. Weighting by effective matches would destroy the responsiveness the model exists for.

Running cameo as its own EWMA let a dropped player read as a 0.02 starter still carrying a 0.30 cameo rate. That reads as "regular substitute" for a player out of the squad.

Where the observations come from

loadInSeasonStarts gives one row per eligible gameweek per player on an eligible team.

  • A start is minutes >= 60, the same rule as the seed. FPL's per-match starts flag is more exact, but a seed and an update that measure different things are worse than a pair that is uniformly approximate.
  • Zero-minute players are recorded, as {started: false, appeared: false}. Without those rows, a player who loses their place would stop being updated and stay "nailed". Hence a loader of its own and its own in-season-starts-gw-N snapshot key. An extra field on the rates loader would silently rebase the xG/xA blend behind PLAYER_FORM_DECAY.
  • Each row carries the observed minutes. Start duration begins at the historical start average when one exists. Otherwise the first current-season start sets the baseline, and the position default applies only when neither source exists. It then follows the same 0.40 EWMA over current starts, so three current 90-minute starts pull a stale short historical duration toward 90.
  • Eligibility matches the xG loaders. Double gameweeks add nothing, and a blank gameweek is no observation, not a benching.

Backtest evidence and a caveat

Walk-forward over 2023/24, 2024/25 and 2025/26 (scripts/backtest/start-rate-alpha.ts). Alpha 0.40 beats 0.60 in all three seasons on Brier score (0.0936 vs 0.0966, 0.1039 vs 0.1101, 0.0940 vs 0.0973). It cuts log loss by about 20% (0.42–0.47 against 0.53–0.58). A faster alpha catches a lost role, but it brings severe overconfidence penalties.

CaveatZero minutes is ambiguous. Benched, rotated, injured, suspended and unregistered all look the same. A layoff therefore reads as role loss, and a returning player needs about five matches to recover. In practice, RotoWire naming them in the XI gives at least 0.9 x 0.75 = 0.675 (the §4.3 blend, before any status discount), whatever the recursion says, and the §4.4 hard gate handles the absence itself.

§4.2Fallbacks

In short: with no history, the model guesses from this season's minutes, or from a flat 0.15 start rate for a new player.

fallbackStartRate = current.minutes <= 0 ? 0.15 : clamp(0.1 + minutes / 1800, 0.15, 0.8) fallbackCameoRate = current.minutes > 0 ? 0.12 : 0.08

A player with no previous season at all (a promoted club's squad, or a new signing) gets a flat seed once this season has match observations (observations.length > 0):

UNKNOWN_START_SEED = 0.15 UNKNOWN_CAMEO_SEED = 0.08

The fallbacks read player.current.minutes, the running total that the recursion is about to replay match by match. Seeding from it would count this season twice at two speeds. The fallbackStartRate terms still apply with zero current-season observations, where they are the only evidence there is.

§4.3Blending

In short: when RotoWire covers the player's team, its lineup counts for 75% of the answer and the role estimate for 25%.

roleStart = blendStartRate(seedStart, observations) // §4.1.1 roleCameo = blendCameoRate(seedStart, seedCameo, observations) // or the current frequency, see below seedWeight = observations.length > 0 ? 0 : 0.25 start = roleStart * (1 - seedWeight) + fallbackStartRate * seedWeight cameo = roleCameo * (1 - seedWeight) + fallbackCameoRate * seedWeight

seedStart and seedCameo are the §4.1 historical rates, or the §4.2 seeds when there is no history. With no observations, the recursion returns the seed unchanged.

The 0.25 fallback term applies only while the player has no current-season observations. It tempers an estimate whose only evidence is last season. Once this season's matches are in, that term only dilutes them: fallbackStartRate is clamped to 0.15–0.80, so it would drag a measured 0.99 down to 0.94 and push a measured 0.02 up to 0.05.

Both start and cameo use the same weights.

rotowireStart = starter ? (confirmed ? 0.96 : 0.90) : 0.10 rotowireCameo = starter ? 0.05 : 0.12 start = rotowireStart * 0.75 + roleStart * 0.25 cameo = rotowireCameo * 0.75 + roleCameo * 0.25

RotoWire's own UNAVAILABLE records then apply. OUT and SUS are rulings, not doubts. They gate as hard as FPL's unavailable codes (§4.4): start and cameo are capped at 0.01. Only QUES is soft. It discounts start by 0.65 and cameo by 0.75, and the model resolves it against FPL's status instead of multiplying the two (§4.4.1).

Start uses the EWMA always; cameo and duration switch at 240 minutes

Start probability always uses the historical-seeded EWMA. Removing the old 240-minute start-frequency override cut held-out start Brier by 0.01542 (95% gameweek-cluster interval 0.01318–0.01748) over 56,569 player-gameweeks. See scripts/backtest/results/tier-c-role.md.

Once eligible observations hold at least 240 total minutes, cameo probability uses the current-season frequency, and expected start duration uses the current-season average across starts. Below that, those two calculations keep their historical blend. The experiment did not test changing them.

§4.5Scenario normalization

In short: start, cameo and no appearance must add to 1, so the model rescales when start and cameo add to more.

normalizeScenarios produces startProbability, cameoProbability and noAppearanceProbability. If start + cameo <= 1, the remainder is "no appearance". Otherwise both are rescaled by their sum and no appearance is 0.

Two made-up players. The arithmetic follows the rule above.

§4.6Expected minutes (selection model)

In short: expected minutes are the chance of starting times a start's length, plus the chance of a cameo times a cameo's length.

expectedStartMinutes = clamp(currentStartDuration(history.startMinutes, observations), 60, 90) expectedCameoMinutes = clamp(history.cameoMinutes ?? CAMEO_MINUTES[position], 1, 45) expectedMinutes = startProbability * expectedStartMinutes + cameoProbability * expectedCameoMinutes

Position defaults:

PositionSTART_MINUTESCAMEO_MINUTES

MID7920

A made-up midfielder with no minute history: start 0.70, cameo 0.20, using the MID defaults.

0.70 × 79 + 0.20 × 20 = 55.3 + 4.0 = 59.3 minutes

How currentStartDuration works

Below the 240-minute role threshold, currentStartDuration starts from the previous-season average. With no historical average, it starts from the first current-season start. It updates only on observations classified as starts:

duration_n = duration_(n-1) * (1 - 0.40) + observedMinutes_n * 0.40

The position default applies only when neither source exists. At or above the threshold, the current-season start average replaces this blend.

§4.8Selection confidence

In short: confidence says how much evidence sits behind the odds, in three levels.

HIGH

Any one of:

  • a RotoWire signal
  • a covered team
  • history.matches >= 10
  • observations.length >= 5

MEDIUM

Any one of:

  • any history (history.matches > 0)
  • any current-season observation (observations.length > 0)
  • current minutes (player.current.minutes > 0)
  • a known chanceOfPlaying

LOW

None of the above.

Five matches take the EWMA most of the way from its seed to what this season says. By then the estimate rests on observed starts, not on last season's rate.
