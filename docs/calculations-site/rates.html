§6

Per-90 rates

This stage turns a player's goals, assists, bonus, saves and cards into a rate for each 90 minutes. It mixes last season with this season, pulls the result toward a sensible prior, and hands the rate on to the fixture step.

§6Per-90 rates and regression

In short: a player's rate starts as a count divided by minutes, then a prior pulls it back until the player has played enough to trust.

§6.1Rate extraction

In short: divide the count by the minutes played, then multiply by 90.

rate per 90 = value / minutes * 90

Made-up numbers: a player has 0.6 xG in 180 minutes. The rate is 0.6 / 180 × 90 = 0.30 xG per 90.

§6.2Regression toward a prior

In short: a player with few minutes gets a rate close to the prior, and a player with many minutes gets a rate close to their own.

The prior counts as 900 minutes (10 matches) of evidence. The weight on the player's own rate is sampleMinutes / (sampleMinutes + 900). At 900 minutes it is one half.

rate = (observedPer90 * sampleMinutes + priorPer90 * 900) / (sampleMinutes + 900)

Made-up numbers: observed 0.50 xG per 90 over 450 minutes, prior 0.20.

  1. Top: 0.50 × 450 + 0.20 × 900 = 225 + 180 = 405.
  2. Bottom: 450 + 900 = 1350.
  3. Rate: 405 / 1350 = 0.30. The player's own rate carries weight 450 / 1350 = 1/3.

§6.3Blending current and historical, then regressing

In short: for bonus, saves, defensive contributions and cards, last season's rate mixes with this season's, then the prior pulls the result back.

2. Cap current rateat anchor × 3.0, upper side only

3. Blendweight = matches / (matches + W)

4. Regressto the prior with 900

rate = historicalRate ?? prior sample = historicalMinutes if current exists: currentWeight = matches / (matches + W) // with a match history | clamp(currentGameweek / 10, 0, 0.6) // without one anchor = rate > 0 ? rate : prior currentRate = min(currentRate, anchor * 3.0) // PLAYER_FORM_WINSOR_RATIO, upper side only rate = rate * (1 - currentWeight) + currentRate * currentWeight sample += currentMinutes * currentWeight rate = clamp(regressPer90(rate, sample, prior, 900), 0, ceiling)

matches is the number of finished gameweeks the player featured in (options.playerForm, §6.3.1). The weight counts the player's own appearances, not the calendar. The old currentGameweek / 10 ramp gave a player with one appearance the same weight as a player with ten. The calendar ramp still applies to a caller that has not loaded match history.

§6.3.1xG and xA: recency-weighted match history

In short: for xG and xA, recent matches count more than old ones, and a long match counts more than a short cameo.

xG and xA use a different current-season blend, regressedFormRate. A player's regressed historical rate (or the neutral price-tier prior) anchors the blend. The current-season share comes from blendPlayerRateByMinutes, which weights each match by recency and by the minutes played in it.

Recency weights: decayi with decay 0.95

Match i counts 0.95^i, where i is how many matches before the most recent one it was played.

weight(i matches before the most recently played) = decay^i observedRate = 90 * Σ(weight_i * value_i) / Σ(weight_i * minutes_i) effectiveMatches = Σ(weight_i) cappedRate = clamp(observedRate, basePrior / 3.0, basePrior * 3.0) blended = (basePrior * priorWeightMatches + cappedRate * effectiveMatches) / (priorWeightMatches + effectiveMatches)

value_i is the raw xG or xA from match i. Constants: decay = 0.95 (PLAYER_FORM_DECAY), priorWeightMatches = 6 (PLAYER_FORM_PRIOR_WEIGHT_MATCHES), and the 3.0 cap (PLAYER_FORM_WINSOR_RATIO).

How much of the blend is this season?

The effective matches are the sum of the weights. Against the prior weight of 6, this season's share is effectiveMatches / (6 + effectiveMatches).

after 2 matches24.5%
after 38 matches74.1%

After two appearances the season adds 1 + 0.95 = 1.95 effective matches: 1.95 / (6 + 1.95) = 24.5%. After 38 it adds 17.15 effective matches: 17.15 / (6 + 17.15) = 74.1%.

Why sum the values, then divide by the sum of minutes

Averaging per-90 rates match by match, as blendPlayerRate does, gives an eight-minute cameo the same say as a full match. Pooling the totals gives a cameo only a cameo's worth of evidence.

Made-up numbers, with the recency weights left out so the point stays plain. Match A: 90 minutes, 0.2 xG. Match B: an 8-minute cameo, 0.4 xG.

  • Rates: A is 0.2 per 90. B is 0.4 / 8 × 90 = 4.5 per 90.
  • Average of rates: (0.2 + 4.5) / 2 = 2.35 per 90. The cameo dominates.
  • Pooled: 90 × (0.2 + 0.4) / (90 + 8) = 54 / 98 = 0.55 per 90.
Defender capA defender's xG is capped at 0.35 per 90 in each match before the blend. No backtest note records a test of this cap.
Backtest evidence and how the constants were chosen
  • Pooling minutes instead of averaging rates was worth 2.0–6.3% rest-of-season rate RMSE on xG across three held-out seasons, and 1.1–1.4% on xA. The anchor's weight is still counted in matches, so priorWeightMatches keeps its meaning.
  • Decay 0.93–0.95 tied on actual-points RMSE and 0.95 won the main split (scripts/backtest/evidence-weights.ts).
  • A three-season (2023/24–2025/26) sweep of the prior weight against next-match xG/xA, scored with genuine previous-season anchors, bottomed at 6 for xG and 4 for xA (flat across 4–8). So 6 covers both within noise.
  • The 3.0 cap bounds single-match spikes, such as a fluke hat-trick, which dominate squared error and revert hardest.
No match history yet: the fallback path

This path needs an in-season match history (options.playerForm, filled by loadInSeasonPlayerRates in lib/historical/loadInSeasonForm.ts, one entry per finished gameweek the player featured in). Without one, xG and xA use cumulative Player.current.expectedGoals / expectedAssists. This happens before any gameweek has finished, or for a caller that has not loaded it.

rate = historicalRate / sourceAttack (or pricePrior with no history) sample = historicalMinutes if current exists: currentWeight = clamp(currentGameweek / 10, 0, 0.6) rate = rate * (1 - currentWeight) + (currentRate / ownAttack) * currentWeight sample += currentMinutes * currentWeight rate = clamp(regressPer90(rate, sample, pricePrior, 900), 0, 3)

Unlike §6.3, this fallback has no cap on the current rate, and it divides each side by the attack of the club that produced it.

The historical anchor

On the match-history path, the historical xG/xA anchor is regressed toward the neutral price-tier prior before it enters the blend:

historicalAnchor = regressPer90(historicalRate, historicalMinutes, pricePrior, 900)

The generic pricePrior is deliberately league-neutral. It is not divided by the current club's attack, so the upcoming fixture multiplier still lowers a player on a weak attack. A historical sample is normalized by the attack of the club that produced it, using the source team's strength from the historical bundle. A transfer therefore does not rescale old production with the new club's attack.

§6.3.2Schedule adjustment: counting the fixture once

In short: the model divides each past match's output by that match's fixture multiplier, so §7's multiplier for the next match does not count fixture quality a second time.

A match against a weak defence produced a higher rate for that reason, and §7's multiplier for the upcoming fixture is about to apply on top. Left alone, the model counts fixture quality twice.

Without the adjustment: counted twice

Past rate, lifted by soft fixtures
→
Blend
→
× upcoming multiplier (§7)

Soft opponents lift the form twice: once in the past rate, once in the next fixture.

With the adjustment: counted once

Past rate ÷ m_i
→
Blend
→
× upcoming multiplier (§7)

The past rate has fixture quality removed, so only the next fixture adds it back.

m_i = attackMultiplier(opponent_i, venue_i) // base = 1; see below sourceAttack = historical source club attack, when available rate = blendPlayerRateByMinutes({ value_i / m_i, minutes_i }, historicalAnchor / sourceAttack)

Made-up numbers: a player's recent form is 0.50 xG per 90, played against fixtures with m_i = 1.25. The next fixture also has multiplier 1.25.

  • Unadjusted: 0.50 × 1.25 = 0.625. The soft run counts twice.
  • Adjusted: 0.50 / 1.25 = 0.40, then 0.40 × 1.25 = 0.50. The soft fixture counts once.
  • Both halves move together. The anchor and the form are both normalized. Normalizing the form alone leaves an inflated anchor against a deflated form estimate, and scores worse than doing nothing in every season tested.
  • No historical sample. The code passes pricePrior as the neutral anchor instead of dividing it by the current team's attack. The current team's attack stays in each upcoming fixture's multiplier, so generic priors keep the team-strength effect.
  • Which strengths m_i uses. It uses the current strength table and leaves base at 1, because the model stores neither a past gameweek's strengths nor its difficulty. It stores only the opponent and the venue, which loadInSeasonPlayerRates attaches to each appearance from the fixture list. Both approximations were measured, not assumed: scoring past matches with today's strengths is better than the walk-forward version, and the asymmetry against a live-FDR upcoming fixture costs 0.001–0.003 RMSE and does not move the bias.
FallbackIf any appearance has no opponent, or faces a team with no strength entry, the whole player falls back to the unadjusted blend, so the model never mixes scales.
What it buys: backtest 2022/23–2025/26

RMSE is a wash. The mean prediction gap between arms is 0.016–0.026 xGI/90 against a residual of 0.17–0.25, so the test cannot resolve it. Bias is where it lands: the absolute bias falls in 7 of 8 season-metric comparisons.

What it does not fix

Splitting that gradient shows most of it is not the schedule. Bucketed by a player's recent run against their own baseline, the tilt is mixed. Bucketed by team level, it is monotone in every season. A player's own xG rate still carries some team quality, so the schedule arm remains an approximation, not a full player-share decomposition.
